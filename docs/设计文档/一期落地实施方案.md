# 圣享 MES 第一期落地方案（数据管理优先）

> 目标：先把真实数据装进系统、能改状态、能出单据，弱化流程与自动扣减。
> 周期口径：一期只做 3 块 —— ①销售订单接单 ②生产单（主单 + 采购单 + 加工单）③库存管理。
> 工序任务报工、质检、排产、销售出库自动扣减等全部放二期，已有功能保留不删。

---

## 一、一期范围与不做清单

| 模块 | 一期做什么 | 一期不做（保留现状 / 二期） |
|------|-----------|--------------------------|
| 销售订单 | ERP 订单入库、人工调状态、明细补齐流转单字段、导出 | 状态的自动流转校验、ERP 回写强约束 |
| 生产单 | 主单新增流转单字段、导出生产流转单；采购单支持成品/原料/辅料采购；加工单统一内外部模板、多工序合并一张单；各单据状态人工调整 | 工序任务报工、报工审核、过程/来料质检、自动排产、齐套校验 |
| 库存 | 手工新增/编辑/删除库存、Excel 导入、字段补齐、全部操作留痕（成品/原料/辅料等由物料分类、客户、供应商自然区分） | 采购入库/生产入库/销售出库自动增减库存的闭环 |

**统一原则**：所有单据（销售订单、工单、采购单、加工单、库存）都提供「人工改状态」能力，状态只做标记，不做流程闸门。所有数量允许人工修正。

## 三、模块一：销售订单接单

### 3.1 状态人工调整（核心）
新增通用接口，允许任意状态互转，只写日志不做校验：

```
PUT /mes/sal/order/changeStatus
{ orderId, targetStatus, reason }
权限：mes:sal:order:edit
```

- 落地：`SalOrderController.changeStatus` → `ISalOrderService.changeStatus`
- 写操作日志（`@Log` 已有）+ 新增状态变更记录表 `qxx_sal_order_status_log`（orderId / fromStatus / toStatus / reason / operator / createTime）
- ERP 字段（accept_status / sync_status）仅展示，**一期不再阻塞状态变更**

### 3.2 ERP 订单入库
- 保留现有幂等 upsert（按 `external_order_no`）
- 一期把「回写 ERP」改为**可关闭**：配置项 `mes.sal.erp-writeback.enabled=false`，关闭后接单/打回只改本地状态
- 前端订单列表增加「ERP 单号 / 来源系统 / 回写状态」筛选，便于对账

### 3.3 销售订单与明细：**一期不改表结构**

工单流转单所需的口部提袋、底板、材质、克重、门幅、损耗率、版辊周长、工艺流程、产品图片等字段
**只加在工单主表**，销售订单与明细保持现状，不新增字段。

### 3.4 ERP 客户 / 产品名称匹配（现状核查结论）

| 场景 | 现状 | 结论 |
|------|------|------|
| 接单（`/open-api/sal/erp/order/receive`） | `resolveClientId`：映射表 → `clientCode` → `clientName` 精确匹配，未匹配返回 null<br>`resolveItem`：映射表(编码/名称) → `mesItemCode`/`productCode` → `productName` 精确匹配，未匹配返回 null | **已实现**：匹配不到只保留 ERP 原始编码/名称文本，**不会把 ERP 的 id 带进来** |
| 接收报价单（`/open-api/sal/erp/quote/receive`） | `SalQuote` / `SalQuoteLine` **没有 clientId、productId 字段**，全部按文本原样落库，不做任何匹配 | **部分实现**：天然不会带错 id，但也不做名称反查，报价转订单时仍需手工选客户/物料 |
| 产品分类 | ERP 无分类字段（`ErpOrderLineRequest` 只有 productCode/productName/spec） | 无需处理，按名称匹配即可 |

一期补齐（不阻断流程，只做提示与反查）：
1. **报价单加两列**：`qxx_sal_quote` 新增 `client_id`，`qxx_sal_quote_line` 新增 `product_id`
2. 报价单接收时按「产品名称 → `md_item.item_name`」、按「客户名称 → `md_client.client_name`」反查并回填 id，**匹配不到留空**
3. 接单 / 收报价的接口响应增加 `unmatchedClients`、`unmatchedItems` 清单（名称 + 行号）
4. 前端接单/报价页面把未匹配行标黄，提示「需先在物料/客户主数据补录」，不做拦截
5. 已在物料主数据的，继续走映射表（`external_mapping`）优先，保证 ERP 编码变更不误伤

> ⚠️ **ERP ↔ MES 产品关联是独立议题，一期只做提示、不阻断**，详见「十一、待记录议题」。

| 业务员 | `salesperson` | varchar(64) | 销售订单 `salesperson` 带出 |

**生产编号规则**：`{销售订单号}-s{序号}`
- 同一销售订单派生第 1 张工单 → `DD20261107006-s1`，第 2 张 → `-s2`
- 无销售订单（手工建单）时，取工单编码 + `-s1`
- 生成时由后端在同一事务内取当前最大值 +1，保证并发不重号

**不生成字段的时机**：建工单时与现在完全一致（只填现有字段）；流转单相关字段在用户点击【生成流转单】时才补齐。

## 五、模块三：库存管理

### 5.1 库存模型：一切来自物料档案（不设库存类型）

库存行只承载「在哪、多少、谁供/谁订」；「是什么、按什么单位」一律由物料档案决定，避免系统被纸袋行业绑死。

| 维度 | 来源 | 说明 |
|------|------|------|
| 成品/原料/辅料/纸边/废纸/外加工纸 | `qxx_md_item.item_type_id`（物料分类） | 不新增 `stock_type`，分类即口径 |
| 订单成品 / 现货成品 / 外采现货 | 工单号 / 客户 / 供应商是否为空 | 有工单或客户=订单成品；无工单无客户=现货；供应商非空=外采 |
| 数量主单位 | `qxx_md_item.unit_of_measure / unit_name` | 纸袋原料 kg、成品 个；文化墙 ㎡、广告门头 根 —— 随物料而变 |
| 辅助单位与换算率 | `qxx_md_item.unit2 / unit2_name / conversion_rate` | 原料 kg↔卷、成品 个↔箱；「装箱数量」即换算率 |
| 装箱规格 | `qxx_md_item.package_spec` | 仅展示，不再在库存表存 `pack_qty` |
| 门幅/材质/克重/纸张来源/用途 | `qxx_md_item.ext_attrs` + 分类属性模板 | 库存列表 JOIN 物料档案展示，不落库存表 |

库存表只新增以下字段：

| 字段 | 列名 | 类型 | 说明 |
|------|------|------|------|
| 客户ID | `client_id` | bigint | 订单成品挂客户；现货/外采为 0 |
| 客户名称 | `client_name` | varchar(255) | 冗余展示 |

数量沿用已有双单位机制，并对物料档案做快照：
- `quantity_onhand`（主单位，权威值）/ `quantity_onhand2`（辅助单位）
- `conversion_rate` 在新增/导入时从物料档案快照，保证历史库存不随物料改单位而漂移

**V191 已移除**：`stock_type`、`roll_count`、`box_count`、`pack_qty`、`width`、`material`、`gram_weight`、`paper_source`、`usage_desc`、`ext_attrs`。

示例（同一套模型适配不同行业）：
| 场景 | 主单位 | 辅助单位 | 展示 |
|------|--------|----------|------|
| 纸袋原料 | kg | 卷（换算率=kg/卷） | 12500 kg / 25 卷 |
| 纸袋成品 | 个 | 箱（装箱 50 个/箱） | 30000 个 / 600 箱 |
| 文化墙 | ㎡ | 张 | 120 ㎡ / 40 张 |
| 广告门头 | 根 | 无 | 36 根 |

| 解析列 | 物料名称/材料名称/产品名称、门幅/规格/尺寸、材质、数量单位、剩余数量（或剩余kg）、辅助单位、剩余辅助数量（或剩余卷/剩余箱数）、装箱数量；兼容 11 月两份原始表头 |
| 导入口径 | **物料分类 + 仓库**（必选），供应商/客户（可选，用于外采与订单成品识别） |
| 物料匹配 | 所选分类内按「名称 + 门幅/尺寸」匹配；匹配不到**自动创建物料** |
| 库存行匹配 | 按唯一键「物料 + 批次 + 仓库 + 供应商 + 工单 + 质量状态」定位；存在则覆盖数量 |
| 单位来源 | 优先物料档案的主单位/辅助单位/换算率；物料档案缺单位时按 Excel 表头（kg/吨/根/米…）或单位列补齐并回写物料档案 |
| 导入模式 | `COVER` 覆盖：直接置为 Excel 的「剩余数量 / 剩余kg」（一期固定覆盖，不做累加）|
| 事务 | 整批一个事务；解析失败行跳过并返回明细，成功行正常提交 |
| 留痕 | 每条写一条 `IMPORT` 流水（含前值/后值），同一 `import_batch_no` |

### 5.5 物料匹配与自动建档规则

一期重点保障：**11 月成品现货表** 与 **11 月原料库存表** 两份能直接导入。

| Excel 来源 | 导入时选择的物料分类 | 匹配键 |
|-----------|--------------------|--------|
| 成品汇总-订单 | 纸袋成品（并填客户/工单） | 产品名称 + 尺寸 |
| 成品汇总-现货 | 纸袋成品（客户/工单留空） | 产品名称 + 尺寸 |
| 成品汇总-外采 | 成品（填供应商） | 产品名称 + 尺寸 |
| 原料库存表 | 纸张 | 材料名称 + 门幅 |
| 纸边库存 | 纸张（或新建「纸边」子分类） | 材料名称 + 门幅 |
| 外加工纸 | 纸张（或新建「外加工纸」子分类） | 材料名称 + 门幅 |
| 辅料 | 辅料 | 辅料名称 |
| 废纸 | 原料/废纸分类 | 原纸名称 + 门幅 |

- 匹配到 → 复用 `md_item`；匹配不到 → 自动创建 `md_item`：
  - `itemTypeId` = 所选分类；编码 = `{分类编码}-{时间戳}`
  - `itemName` = 名称，`specification` = 门幅/尺寸
  - 主单位/辅助单位/换算率按 Excel 单位与装箱数量写入；门幅/材质写入 `ext_attrs`（PAPER_WIDTH / PAPER_TYPE）
  - 导入结果标明「自动新建」条数
- 尺寸缺失（订单表、外采表）时，匹配键降级为「产品名称」，并在结果页提示可能存在同名合并

## 十一、ERP ↔ MES 主数据关联（已在一期落地）

**问题**：ERP / 老 SRM 与 MES 是两套独立主数据，靠「名称匹配」不可靠（同名不同规格、改名都会漏）。

**落地方式（V190）**：
1. 复用 `qxx_sys_external_mapping`：`system_code` = ERP/SRM，`entity_type` = CLIENT/ITEM，`external_code` = 外部编码（缺省用名称），`local_id` = MES 客户/物料 ID
2. 接单弹窗 `AcceptDialog` 提供 MES 客户 + 每行 MES 产品选择，首次确认即写映射
3. `GET /mes/sal/order/acceptDefaults/{orderId}` 按映射回填默认关联（编码优先、名称兜底），前端可调整
4. ERP/SRM 来源订单只要仍有一行产品未关联就阻断接单（后续转工单/工艺路线依赖 `product_id`）
5. 名称匹配仅作为首次映射的**建议值**，最终以人工确认的映射为准

**后续可增强**：映射维护页 + Excel 批量导入；历史单据后台回填。
