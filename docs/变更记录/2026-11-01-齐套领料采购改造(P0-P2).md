# 2026-11-01 齐套 / 领料 / 采购改造记录（P0–P2）

> 范围：工单齐套检查、产品级 BOM、用量方式与单位换算、库存双单位、领料/备料单、采购向导供应商与价格。
> 环境：本地开发（后端 :8082，前端 :5173，MySQL :3307，Flyway 最新版本 **V166**）。

## 1. 背景与目标

- 原系统齐套只覆盖工序 BOM，缺少产品级主料/辅料；纸张等主料无法按「每件用量」配置。
- 库存只维护主单位数量，缺少辅助单位（卷/吨）记录与换算，领料/采购无法按业务单位核对。
- 采购向导供应商只读、明细无单价、无默认价格源，审批前需要人工补价且容易漏补。
- 另有一批状态/字典类缺陷（领料状态、作废单展示、采购下单后可改、0 价审批）需先修复。

## 3. P1 齐套与领料能力

### 3.1 数据模型（V165）

- `qxx_pro_workorder_bom`：
  - `quantity_mode`（`PER_UNIT` 按件用量 / `TOTAL` 整单总量）
  - `bom_source`（`PRODUCT` 产品 BOM / `PROCESS` 工艺路线 BOM）
  - `scrap_rate`（损耗率 0~1）
  - 数量精度统一 `decimal(18,4)`（`quantity` / `total_quantity` / `total_quantity2`）
- `qxx_wm_material_stock`：新增 `quantity_available2`，`quantity_onhand/onhand2/available` 精度提升
- `qxx_wm_transaction`：`quantity/quantity2` 精度提升

### 3.2 统一计算服务（新增 `MesQuantityService`）

- 单位模型：`md_item.unit_of_measure` 主单位（库存基准）、`unit2` 辅助单位、`conversion_rate` =「1 主单位 = N 辅助单位」。
- 需求模型：
  - `PER_UNIT` → 单位用量 × 工单数量 ×（1+损耗率）
  - `TOTAL` → 整单总量 ×（1+损耗率）
  - 已落库 `total_quantity > 0` 视为人工覆盖，直接采用；`0/NULL` 回退计算。
- 所有业务单位统一折算到物料主单位后再进齐套/领料/库存计算。
- 库存行懒归一：历史行若按辅助单位记录先折算；本身即主单位的行刷新单位/换算率快照并补记辅助数量（已记录的部分卷保持不变）。

### 3.3 产品 BOM 合并与重复物料

- 工单创建/保存 BOM 时自动合并 `qxx_md_product_bom`（`enable_flag='1'`），生成 `processId=null`、`processName=产品级原料`、`bom_source=PRODUCT` 的行。
- 同一物料同时来自产品 BOM 与工序 BOM：以工序 BOM 为准（合并时跳过、保存前再按 `itemId` 去重），齐套看板返回 `duplicateBomWarnings` 提示。
- 前端新建工单时同步展示产品级原料分组，可手工调整用量方式/单位/损耗率。

### 3.4 齐套与单据生成

- 齐套计算：需求（先业务单位、再折算主单位）对比「可用库存 + 本工单已备料」，返回 `bomUnitName/bomRequiredQty/quantityMode/bomSource`。
- 领料单/备料单：`processId=null` 生成一张「产品级备料单」，行数量写主单位；幂等键用工序或 0 哨兵。
- 退料、成品出库、库存变动均先归一到主单位再运算，并维护 `onhand2/available2`。

### 3.5 库存双单位规则

- `quantity_onhand / quantity_available` 为权威值（主单位）。
- `quantity_onhand2 / quantity_available2` 为辅助单位记录值：部分卷出库/发料时不减少，**主单位数量清零时才归零**。

## 4. P2 采购向导价格

### 4.1 数据模型（V166）

- `qxx_md_item`：`default_purchase_price`、`default_tax_rate`（兜底价）
- `qxx_md_item_vendor`：`purchase_price`、`tax_rate`、`currency`（按供应商报价，优先）

价格口径统一为「元 / 主单位」。

### 4.2 向导能力

- 候选供应商：仅该物料在 `qxx_md_item_vendor` 中已启用（`enable_flag='1'`）的供应商，首选排第一，可切换，可清空为「待定」。
- 默认价格：所选供应商报价 → 物料默认价 → 空（`priceSource = VENDOR / ITEM / NONE`）。
- 明细行可改价：单价/税率可编辑，金额 = 数量 × 单价（后端重算，2 位小数）；按供应商分组生成多张采购单。
- 审批仍强制单价 > 0（P0 规则不变），草稿允许 0 价。
- 主数据维护：物料页「默认采购价/默认税率」；供应商页物料清单「采购价/税率」列。

- 后端单元测试全绿（`mvn -pl ruoyi-system -am test`），基线 567 项，本轮新增「落库总量为 0 回退计算」用例后为 568 项、0 失败。
- V164/V165/V166 均 `success=1`。
- 真实接口实测（工单 241「奔趣纸袋 小号」）：
  - 保存无 `bomSource` 的 BOM → 自动合并产品级原料 `AUX-ROPE-001`；齐套提示 3 条重复物料。
  - 纸张行改为 `TOTAL 1.5 吨` → 齐套 BOM 用量 1.5 吨、需求 2.1521 卷（按物料换算率 0.697）。
  - 生成单据产出「产品级原料」领料单（`processId=null`）。
  - 领料预占后库存行写入 `unit2/换算率/onhand2/available2`；取消后可用量还原。
  - 采购向导：非法供应商被拒；切换供应商价格联动（480→520）；提交后行 `unit_price/amount/tax_rate` 与头 `total_amount` 正确；有价审批通过、0 价审批被拦。
- 前端：`vue-tsc` 未新增类型错误；Vite 已热更相关页面；齐套看板「来源/重复提示」已在浏览器验证。

## 8. 本轮自检发现并修复的问题（CRT）

| 级别 | 问题 | 修复 |
|------|------|------|
| 🔴 | 库存流水入库时辅助数量重复累加（先按「变动后」总量折算，再加本次辅助数量，导致翻倍） | 改为按「变动前」主单位数量折算后再加本次辅助量：`applyAuxQuantity(...)` 传入 `onhandBase/availBase` |
| 🟠 | 历史 BOM 行 `total_quantity=0` 被当成人工覆盖值 → 需求为 0、齐套误判充足 | `requiredTotalQty` 仅当落库总量 > 0 才采用，否则按用量方式计算（含单测） |
| 🟠 | 领料发料把库存扣到 0 时 `onhand2/available2` 未归零，双单位账实不符 | `deductOnhandAndWriteIssueOut` / `issueOutSingleBatch` 在清零时同步归零辅助单位 |
| 🟠 | 退料回库未做单位折算、未回加可用量、未维护辅助数量，流水/追溯单位写成业务单位 | `WmRtIssueServiceImpl`：批量加载物料、`quantityRt` 折主单位、onhand/available 同步回加、维护 `onhand2/available2`、流水与追溯写主单位 |
| 🟡 | 采购向导提交未校验数量，可能生成 0 数量明细；工单不存在时 NPE | 跳过 ≤0 数量行并在全部无效时返回明确提示；`buildPurOrderWizard` 增加工单存在性校验 |

## 9. 已知限制 / 待办

1. **主数据需业务维护**：`md_item` 当前纸张为「主单位=卷、辅助=吨、换算率 0.697」；若按「主单位=吨、辅助=卷、1 卷=2 吨」管理，需改为主单位 `TON`、`unit2=ROLL`、`conversion_rate=0.5`。代码无硬编码。
2. `qxx_md_item_vendor` 存量 2 条记录 `vendor_name` 为空，建议补齐；前端在名称为空时显示「供应商-{id}」兜底。
3. 旧工单（已存在 BOM 行且前端携带 `bomSource`）编辑时不会再次自动合并产品 BOM，仅新建/无来源提交时合并；如需补历史数据，可对目标工单做一次「保存 BOM」或数据修复。
4. 价格字段使用 `<if test="!= null">` 更新，暂不支持把已维护价格清空为 NULL（如需清空需直接维护数据库或后续加显式清空接口）。
5. 历史库存行的双单位归一为「懒归一」：首次入库/发料/退料时生效，未发生业务前辅助数量可能仍为 0。
6. 采购向导弹窗的浏览器点击验证受测试窗口宽度限制，待人工确认。

## 10. 兼容与回滚说明

- 三份迁移均为 `ALTER`（V164 为幂等 DML），无破坏性删列/改语义；回滚需人工 `ALTER` 逆向，不建议在生产直接回滚。
- 存量工单/领料/采购数据保持可读：新增列均有默认值或允许 NULL；齐套/领料在读取时兼容历史单位与 0 值总量。
