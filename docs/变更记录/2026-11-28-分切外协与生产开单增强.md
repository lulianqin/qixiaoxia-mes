# 2026-11-28 分切外协 / 单据配置 / 移动端库存变更说明

> 范围：分切外协识别与开单入口、母卷实例发料与母子追溯、生产开单「单据配置」细节、移动端库存现有量。
> 环境：本地开发（后端 :8081，MySQL :3307，Flyway 最新版本 **V223**）。
> 关联文档：《[多工厂外协设计](../设计文档/多工厂外协设计.md)》（外协通用模型，本文只写分切增量）。

## 1. 背景与目标

| # | 问题 | 目标 |
|---|------|------|
| 1 | 分切外协没有开单入口，工单的工序单据都集中在「单据配置」页开 | 分切单并入单据配置页，与采购单/加工单同页维护 |
| 2 | 工序主数据没有「分切」分类，只能按工序名称或编码判断 | 用可维护的**业务类型**标识，不再依赖名称/编码 |
| 3 | 分切发料只按 `item + batch` 出库，母卷与分切出的子件**追溯断链** | 发料行直接绑母卷实例，子件挂 `parent_instance_id` 闭环 |
| 4 | 移动端查不到库存现有量 | 移动端补「库存现有量」页，支持下钻实物实例 |
| 5 | 单据明细数量默认可空、单位只能选该物料主/辅单位 | 数量默认 0 且必填；单位改为全量单位下拉 |

## 3. 分切外协

### 3.1 识别口径：工序业务类型（V222）

- `qxx_pro_process` 新增 `biz_type`：
  - `NORMAL` — 普通工序（默认），开单走采购单 / 加工单；
  - `SLITTING` — 分切工序，单据配置里生成**分切单**，走分切外协策略。
- 字典 `mes_process_biz_type` 同步登记；历史数据中 `process_code = 'SLITTING'` 的工序自动回填为分切，其余保持普通。
- 工序管理页新增「业务类型」列与下拉（`frontend/src/views/mes/pro/process/index.vue`）。
- 业务类型需贯穿到工单：`ProRouteProcessMapper.selectProRouteProcessByRouteId`、`ProWorkorderProcessMapper.selectByWorkorderId` 均 left join 带出 `bizType`；`ProWorkorderFullServiceImpl.toRouteProcess()` **必须显式透传 bizType**（否则工单快照丢字段，前端无法识别分切）。
- 后端判定入口统一为 `OutsourceServiceImpl.resolveSourceTypeFor(req)`，优先级：请求显式 `sourceType` → 工序编码推断 → 工序主数据 `bizType` 兜底。**禁止**再按工序名称判断。

### 3.2 分切单融入单据配置

- 分切单本质仍是外协单：`WmOutsourceOrder` + `sourceType = 'SLITTING'`，与加工单同存 `processDocs`，由前端按 `docKindOf()` 区分。
- 「单据配置」页新增**分切单**按钮，支持两种生成方式：
  1. 手工新增分切单卡片；
  2. 按工序配置**同步**（工序 `bizType = SLITTING` 的行同步生成分切单，普通工序行生成加工单）。
- 前端 `docSync.ts`：`DocKind` 增加 `'SLITTING'`，新增 `docKindOf()` / `isSlittingRow()` / `kindLabel()`；同步与比对时**分切单与加工单互不串单**（开单类型变更会提示「原单据未自动迁移」，不静默改单）。
- `SlittingDocCard.vue`（369 行）字段：分切商、开单日期、申购人、送货地址、分切工序行（物料/数量/单位/备注）、**母卷发料明细**。
- 已生成的单据列表按 `sourceType` 打「分切单 / 加工单」标签。
- 单据保存为 `DRAFT` 外协单，**发料在实际发料环节执行**（不随保存过账）。

### 3.3 母卷实例发料（V223）

数据模型：

| 表 | 字段 | 说明 |
|----|------|------|
| `qxx_wm_outsource_issue_line` | `instance_id` | 绑定的母卷实例（`qxx_wm_stock_instance.instance_id`） |
| 同上 | `instance_code` | 实例编号快照，发料后仍可读，便于打印/对账 |

前端（`SlittingDocCard.vue`）：

- 「母卷实例」下拉数据源 `availableInstances`（按物料 + 仓库 + 批次过滤，接口 `/mes/wm/stock_instance/available`）；
- 选项文案 `实例号（余X单位）`；
- 选择后自动带出批次 / 仓库 / 单位，数量默认该卷剩余量，`max` 限制为该卷剩余量。

后端（`OutsourceServiceImpl`）：

| 环节 | 方法 | 行为 |
|------|------|------|
| 校验 | `validateIssueLineInstance(line)` | 实例存在、物料一致、剩余量 > 0，回填编号/批次/仓库 |
| 校验 | `validateSlittingInstanceBound(sourceType, lines)` | 分切单**必须**选母卷；物料已有在库实例却未选 → 直接拦截 |
| 扣减 | `deductInstanceIfBound(line, order)` | `adjustRemaining` 扣实例剩余 + 按实例所属 `material_stock_id` 加锁精确取桶 |
| 记账 | `applyStockContext` | 用实例的批次/仓库/供应商/workorder 覆盖 6 维库存桶上下文 |
| 单位 | `toBaseQuantity` | 走 `MesQuantityService.toBaseQty` 折算主单位后再扣减 |
| 回写 | `bindSlittingSourceInstance(order, lines)` | 母卷实例回写 `order.source_ref_id` |
| 发料 | `issueOneLine(line, order)` | 单行发料统一出口，绑实例走实例扣减，未绑实例保持批次 FIFO |

### 3.4 结果回写与母子追溯

- `SlittingResultStrategy.resolveParentInstanceId(order)`：优先取 `source_ref_id`，缺失时回退「发料行唯一实例」兜底。
- 录入分切结果生成子件实例时写入 `parent_instance_id = 母卷实例`，行业属性（门幅/克重等）写 `ext_attrs`。
- 追溯表 `qxx_pro_material_trace`：父节点绑实例时节点类型记为 `STOCK_INSTANCE`，链路 `STOCK_INSTANCE → OUTSOURCE_ORDER`。

### 3.5 一并修复：实例辅助数量被清零

`WmTransactionServiceImpl` 若先 `applyAuxQuantity/applyInstanceAux` 再 `setMaterialStockId`，会把实例数辅助数量算到错误的桶上（实测 3 卷变 0）。已调整为**先** `stock.setMaterialStockId(existing.getMaterialStockId())`，**再**累加辅助数量。

## 4. 生产开单「单据配置」细节

| 项 | 调整 | 位置 |
|----|------|------|
| 采购单明细数量 | 默认 `0`，必填，红框标识；提交前 `quantity > 0` | `PurchaseDocCard.vue`（`addLine` / `isQtyValid`） |
| 加工单/分切单工序数量 | 同上，按 `planQty > 0` 校验 | `ProcessDocCard.vue`、`SlittingDocCard.vue` |
| 采购单单位 | 改为下拉，选项为**全部启用单位**（`listAllUnitmeasure`），默认跟随物料主单位，可手选其它单位，**不限制**该物料主/辅单位；选择后回写 `unitOfMeasure = unitCode` | `PurchaseDocCard.vue`（`unitOptions` / `onUnitChange`） |
| 提交前整体校验 | 采购单：供应商必填、至少一行、每行数量 > 0；加工单/分切单：外协（非内部加工）供应商必填、至少一行、每行数量 > 0，提示文案区分「加工商 / 分切商」 | `edit.vue` → `validateDocs()` |
| 回显/提交 | 单据带 `issueLines` 往返；草稿更新时**有明细即整体替换**发料行 | `edit.vue`、`ProWorkorderFullServiceImpl.updateDraftProcDoc` |

## 9. 已知限制 / 待办

1. **多母卷分切单无法唯一确定父件**：一张分切单绑多个母卷时，子件实例只能不挂 `parent_instance_id`（仅 warn 日志）。如需精确追溯，按「一单一卷」开单，或后续在结果录入时逐件指定来源母卷。
2. **权限**：母卷下拉依赖 `mes:wm:stock_instance:query`，非 admin 的开单角色需在角色里勾选，否则下拉为空且发料被拦。
3. **测试残留数据待确认清理**：外协单 77（ISSUED）、78（PROCESSING，含收货行）、子件实例 8（OUTSOURCED）、库存桶 527 少 3kg、实例 4/5 各少 1/2kg，均落在测试物料 997/998 上。已执行单不能走删除接口。
4. 旧表 `qxx_wm_roll_detail` 仅停用菜单与权限，未删表；确认无引用后再单独清理。
5. 分切单发料行既可在单据配置页录入，也可在发料环节补录；两条路径都以「分切单必须有母卷」为前提。
6. 本批改动**仅本地**，未发布到生产。

## 10. 兼容与回滚

- V222 为加列 + 字典 + 幂等回填，V223 为加列，均无破坏性变更；存量工序 `biz_type` 默认 `NORMAL`，存量发料行 `instance_id` 为 NULL 时保持原批次 FIFO 行为。
- 如需回滚：先确认无分切单依赖，再逆向 `ALTER`（删列 / 删字典项），不建议在生产直接回滚；功能层面可先停用分切单入口（工序 `biz_type` 改回 `NORMAL`）实现软回退。
